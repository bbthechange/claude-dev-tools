01

First-run flow

0 / 4
A cold open. Land → connect the coordinator → capture one idea → watch it become a dossier. The thesis: prove the loop in under two minutes, no account walls.
▸ full picture — if the headers + diagram weren’t enough

The risk in first-run isn’t confusion, it’s disbelief — the value prop ("you’ll barely touch this") is unintuitive until seen. So the flow is built to manufacture one real end-to-end moment fast: a seeded sample idea that visibly flows to a dossier, rather than a feature tour.

Coordinator pairing is the only hard step; everything else is skippable. We deliberately defer voice capture and project pickers to keep the cold path to four screens, since returning users get the rich capture screen anyway.

02

Returning to a full Inbox

0 / 3
The 80% case: you open it cold with several things queued. Ordering and bulk-clear are the whole game here.
▸ full picture

This is where the product earns trust or loses it. If the queue is sorted by anything other than tier-then-stakes, you’ll learn to distrust the order and re-scan everything — which destroys the 60-second promise.

The bulk "approve all recommended" control is contentious: it’s the fastest path but also the one most likely to rubber-stamp. The recommendation keeps it but makes its summary explicit before commit.

● Flow E

The Board — situational awareness

In 5 seconds: is anything waiting on me, and is the machine healthy? Status strip, the pinned amber Waiting lane, then the lifecycle spine.

Read model over beads — local and remote are the same view.

● Cross-cut #1

The Inbox is the product

One ranked, batched queue. A blocking stage-gate dossier, a proactive overview to read, a pair session — each is one row, never a second ping.

Your “no” must be as cheap as your “yes.”

● Flow B + F — the core

The dossier is the whole product

Not a one-question popup — a skimmable technical document that resolves a whole stage. Contextual TL;DR (what · where it fits · what I need), a jump index with live counts, "where it sits" + per-flow diagrams, and a Skim ⇄ Full toggle so headers/diagrams suffice — or expand the full argument.

Every call carries a recommendation and four affordances: Approve (one tap), pick an alternative, edit the recommendation, or react. Mix freely across 14 calls, bulk-approve the rest, submit once. The same machinery, in overview mode, is the proactive "how it fits together" brief (Flow F).

Checkbox → deterministic & instant. Reconciler only reads your edits.

● Flow B · step 6

One pass cleared the stage

A receipt of the whole batch — approved / picked / edited counts, what unblocked, where edits went. You never go back to check.

Confirm — so you trust it landed without checking.

● Flow A — intake

Raw thought → pipelined work

~5s: one box, a project (or “let it pick”), a tapped entry-intent preset (entry stage + gate aggressiveness). An enricher dedups and scopes it.

You declare entry intent. The system never guesses the size.

● Flow C — capacity

One usage authority, honest state

5h ceiling, 7d budget, today’s spare line vs. actual. Per-project mode is flippable; “stopping…” renders honestly — never optimistic.

Agents downgrade their own env; only you promote to full.

● Flow G — failure

Progressive disclosure across a boundary

Glance → human-worded summary → forensic. Metadata always syncs; the raw stream-json never does — fetched on demand, redacted, never persisted.

Surface the silent failures loudest. Loud ones self-heal.

Try the dossier → open the amber card, hit SKIM/FULL, tap a section in the index. On any call: Approve, Options, Edit, React. Use “approve all” then change a few, watch the counter and submit summary. The 2nd Inbox row opens it in proactive overview mode.

Same read model, wider glass

“Remote” isn’t a new datastore — the same beads sync at desk width. The amber lane stays pinned no matter the viewport.
